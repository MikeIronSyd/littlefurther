# P07 private StudyCircle interface research

Recorded 8 October 2026, Africa/Lagos. Source and image inspection only; no P07 implementation, live browser verification, new visual approval or learner benefit is claimed.

## Goal

Add voluntary private peer accountability to the connected learning journey. A learner can create or join an invitation-only circle, inspect its audience, explicitly share a commitment/check-in copy, and send preset encouragement. Explain and support the full membership/shared-copy lifecycle while preserving independent private study.

## Constraints

- No fourth navigation destination, full chat, automatic invitations/messages, runtime AI, remote-peer promise, new identity or invented learner outcomes.
- Use the existing DOM helpers: learner/circle/copy text is appended as text, never interpreted HTML. Locale changes update bound labels while preserving the same input nodes and learner-provided text.
- The server owns membership checks, field allowlists, token hashing/expiry/redemption, transactions, cleanup and canonical SQLite state. Hiding a UI control never substitutes for authorization.
- Keep invite tokens only in the active page's memory; no URL, local/session storage, analytics, logs or saved drafts. The app's only non-sensitive local storage remains theme/sidebar enums. Display the returned token once in a selectable read-only field; manual copy/paste into a second local account avoids an unneeded Clipboard API dependency.
- Show current audience before sharing. Disclose message/type, display name and posting time; keep plans, resources, reflections and unshared activity outside the preview. Explain that later private edits do not change this copy and deletion cannot recall what someone already saw.
- Existing learner/history evidence remains private and intact through circle leave/removal/closure. The owner closes explicitly rather than leaving or transferring ownership silently.

## Proposed implementation contract

1. From My learning (including the no-plan screen), open Study together without changing the three primary routes. Fetch current circles and render loading, empty, ready, failed and signed-out states.
2. Create a named circle or paste an invitation. Re-read authoritative persisted state after success; open the joined/created circle. Names and codes are never placed into executable markup or browser persistence.
3. On the circle view, show its name, member audience and optional private-plan context. The owner can disclose invitation/member controls. A member can open a commitment/check-in editor or interact with a persisted shared copy.
4. Editing a shared copy's kind/body updates the exact local preview. Sharing requires a labelled final action; the outbound body contains only explicitly approved fields and the idempotency identifier. Later private-plan changes do not update it. Draft input survives theme/language changes and failed requests.
5. Preset encouragement is an explicit action attached to a saved copy. Hide unavailable owner/member/author actions for clarity while server checks remain authoritative.
6. Destructive actions open inline confirmation with cleanup and retained-history copy. Success returns to authoritative list/detail; a membership-denied response removes obsolete displayed content. Already-seen information cannot be recalled.
7. A request's result only changes the view that initiated it. Retried uncertain mutations reuse the exact request body/key when the backend supports replay. Known-saved refresh failures retry GET only. Avoid generic stale-plan text in peer errors.

## Done When

Root's subsequent scoped decisions: use `commitment` / `check_in` and a message of at most 280 characters, without a shared date field. Joining must explain before redemption that the learner's display name becomes visible to the circle and member display names become visible to them. Invitations use manual paste; the raw value is returned once, and an exact creation retry returns metadata with `token: null`, requiring honest revoke/new guidance rather than a claim that the original secret can be recovered. Root agrees to the empty-plan entry and unchanged three-destination shell. Exact limits/routes/types remain dependent on the final contract.
